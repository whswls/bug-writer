시작하기 전에 — 명령 창 여는 법

이 문서의 명령어는 PowerShell 또는 명령 프롬프트(cmd) 에 입력합니다. 둘 중 아무거나 써도 되고, 여는 방법은 아래와 같습니다.

PowerShell 열기

  • 시작 버튼 우클릭 → 터미널 또는 Windows PowerShell
  • 또는 Win + R → powershell 입력 → 엔터
  • 또는 시작 메뉴에서 powershell 검색

명령 프롬프트(cmd) 열기

  • Win + R → cmd 입력 → 엔터
  • 또는 시작 메뉴에서 cmd 검색

특정 폴더 위치에서 바로 열기

경로를 일일이 입력하기 번거로울 때 씁니다. 탐색기에서 원하는 폴더를 연 다음, 주소창에 cmd 를 입력하고 엔터를 누르면 그 폴더 위치에서 명령 창이 열립니다.

알아두면 편한 것

동작방법
붙여넣기마우스 우클릭 (또는 Ctrl+V)
이전 명령 다시 쓰기↑ 방향키
폴더 이동cd 경로
현재 폴더 내용 보기dir
화면 지우기cls
참고

이 문서의 명령어는 회색 상자 안에 있고, 오른쪽 복사 버튼을 누르면 그대로 복사됩니다. 명령 창에 우클릭으로 붙여넣고 엔터를 치면 됩니다.

01

Node.js 설치

왜 압축 파일인가

설치 프로그램(.msi)은 관리자 권한을 요구할 수 있습니다. 압축 파일(.zip) 버전은 풀기만 하면 되므로 권한이 필요 없습니다.

다운로드

node-v24.19.0-win-x64.zip

참고

공식 페이지에서도 받을 수 있지만 드롭다운에서 Standalone Binary (.zip) 을 찾아야 해서 번거롭습니다. 위 링크가 같은 파일입니다.

압축 해제

C:\node.js\ 폴더를 만들고 그 안에 압축을 풉니다. 최종 경로가 아래처럼 되어야 합니다.

C:\node.js\node-v24.19.0-win-x64\node.exe
주의

Program Files 나 C:\ 루트에 바로 풀지 마세요. 쓰기 권한 문제가 생깁니다.

회사 정책상 C:\node.js 도 막힌다면 C:\Users\본인계정\node.js 로 하고, 이후 나오는 경로를 모두 그에 맞게 바꾸세요.

경로 등록 (PATH)

이걸 해두면 어느 위치에서든 node 명령을 쓸 수 있습니다. PowerShell을 열고 아래를 붙여넣으세요. 관리자 권한이 필요 없습니다.

[Environment]::SetEnvironmentVariable("Path", [Environment]::GetEnvironmentVariable("Path","User") + ";C:\node.js\node-v24.19.0-win-x64", "User")
필수

실행한 뒤 PowerShell 창을 완전히 닫고 새로 여세요. 그러지 않으면 반영되지 않습니다.

확인

node -v

v24.19.0 이 나오면 성공입니다.

02

PowerShell 준비

Node.js는 되는데 npm 만 안 되는 경우가 있습니다. PowerShell이 스크립트 실행을 막고 있어서입니다.

npm : 이 시스템에서 스크립트를 실행할 수 없으므로 ... npm.ps1 파일을 로드할 수 없습니다.

아래 세 가지 중 하나를 쓰면 됩니다.

A. 현재 창에서만 — 가장 간단

Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass

창을 닫으면 원래대로 돌아가 시스템 설정을 건드리지 않습니다. 다만 PowerShell을 새로 열 때마다 다시 입력해야 합니다.

B. 매번 자동 적용

창을 열 때마다 자동으로 설정되게 합니다.

New-Item -ItemType File -Path $PROFILE -Force
notepad $PROFILE

메모장이 열리면 아래 한 줄을 넣고 저장하세요.

Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force

C. 명령 프롬프트(cmd) 사용

cmd는 이 정책의 영향을 받지 않습니다. PowerShell 대신 cmd를 쓰면 아무 설정 없이 동작하고, 이 문서의 명령어는 cmd에서도 모두 동일하게 작동합니다.

참고

회사 그룹 정책이 걸려 있으면 -Scope CurrentUser 로 영구 변경하는 건 실패합니다. 그럴 땐 A, B, C 중 하나를 쓰세요.

03

Playwright 설치

작업 폴더를 만들고 설치합니다. 폴더 위치와 이름은 자유입니다.

mkdir C:\Users\본인계정\auto
cd C:\Users\본인계정\auto
npm init -y
npm i -D @playwright/test
npx playwright install chromium

마지막 줄에서 브라우저를 내려받습니다. 용량이 커서 몇 분 걸립니다. 아래처럼 다운로드 완료 메시지가 여러 줄 나오면 성공입니다.

Chrome for Testing ... downloaded to C:\Users\...\ms-playwright\chromium-...
04

녹화로 스크립트 만들기

코드를 직접 쓰지 않아도 됩니다. 브라우저에서 클릭하면 코드가 자동으로 만들어집니다.

npx playwright codegen https://테스트할주소
확인

사내 서버를 대상으로 한다면 VPN 연결을 먼저 확인하세요.

사용법

창이 두 개 뜹니다.

창역할
왼쪽 (브라우저)평소처럼 클릭·입력
오른쪽 (Inspector)동작이 코드로 실시간 기록됨

왼쪽 브라우저에서 자동화하고 싶은 동작을 그대로 하세요. 다 했으면 오른쪽 창 상단의 복사 버튼을 누릅니다.

모바일 화면으로 녹화

npx playwright codegen --device="iPhone 15" https://테스트할주소
05

스크립트 저장

폴더 만들기

mkdir C:\Users\본인계정\auto\tests

Playwright는 tests 폴더 안의 .spec.js 파일을 자동으로 찾아 실행합니다.

파일 만들기

notepad C:\Users\본인계정\auto\tests\login.spec.js

"새로 만들까요?" 라고 물으면 예를 누르고, 복사한 코드를 붙여넣은 뒤 Ctrl+S.

주의

탐색기에서 새 텍스트 파일을 만들어 이름을 바꾸면 login.spec.js.txt 처럼 확장자가 잘못 붙기 쉽습니다. 위 notepad 명령으로 만드는 게 안전합니다.

탐색기를 쓴다면 상단 보기 → 파일 확장명을 반드시 켜두세요.

파일 이름 규칙

무엇을 하는 스크립트인지 알 수 있게 지으세요.

login.spec.js
category-filter.spec.js
search.spec.js
06

실행

작업 폴더(tests 안이 아니라 그 상위)에서 실행합니다.

cd C:\Users\본인계정\auto
npx playwright test --headed
  • --headed — 브라우저를 실제로 띄워 동작을 눈으로 확인
  • 옵션을 빼면 화면 없이 백그라운드로 실행 (더 빠름)

결과

✓ 1 tests\login.spec.js:3:5 › test (4.9s)
1 passed (5.9s)
표시의미
passed통과
failed실패 — 어느 줄에서 멈췄는지 함께 표시됨

리포트 보기

npx playwright show-report

브라우저로 열리며 단계별 소요 시간과 실패 지점 스크린샷을 확인할 수 있습니다.

07

자주 나오는 오류

node / npm / npx 용어가 인식되지 않습니다

PATH가 등록되지 않았거나, 등록 후 창을 새로 열지 않았습니다. 현재 창에서만 임시로 해결하려면:

$env:Path += ";C:\node.js\node-v24.19.0-win-x64"
".\node" 를 입력하십시오 라는 안내가 뜸

PowerShell은 현재 폴더의 실행 파일을 그냥 실행하지 않습니다.

.\node -v

PATH를 등록하면 이 문제는 사라집니다.

npm.ps1 파일을 로드할 수 없습니다

실행 정책 문제입니다. 2번 항목을 참고하세요.

Error: No tests found

tests 폴더에 .spec.js 파일이 없습니다.

dir tests
  • 폴더가 없다 → 만들어야 합니다
  • login.spec.js.txt 로 보인다 → 확장자가 잘못됐습니다. .txt 를 지우세요
Test timeout of 30000ms exceeded

기본 제한 시간 30초 안에 페이지가 안 열린 경우입니다. 테스트 서버는 로딩이 느린 경우가 많아 자주 발생합니다. 스크립트를 열어 두 군데를 수정하세요.

test('test', async ({ page }) => {
  test.setTimeout(300000);
  await page.goto('https://테스트할주소', { waitUntil: 'domcontentloaded' });
수정효과
test.setTimeout(300000)제한 시간을 5분으로
waitUntil: 'domcontentloaded'이미지까지 다 받길 기다리지 않고 진행

두 번째가 특히 효과적입니다. 클릭 동작에는 이미지 로딩이 필요 없기 때문입니다.

패키지 설치가 멈추거나 ETIMEDOUT 오류

사내 프록시 설정이 필요할 수 있습니다. 인프라 담당자에게 프록시 주소를 문의하세요.

08

더 해보기

검증 추가하기

녹화만 한 스크립트는 클릭만 하고 끝이라 화면이 깨져도 통과합니다. 검증문을 넣어야 진짜 테스트가 됩니다. 파일 맨 위 import를 먼저 확인하세요.

import { test, expect } from '@playwright/test';

원하는 위치에 추가합니다.

// 특정 텍스트가 보이는지
await expect(page.getByText('로그인')).toBeVisible();

// 입력창이 있는지
await expect(page.getByRole('textbox', { name: '아이디' })).toBeVisible();

// 페이지 주소가 맞는지
await expect(page).toHaveURL(/mypage/);

계정 정보 분리하기

녹화하면 아이디·비밀번호가 코드에 그대로 남습니다. 스크립트를 공유할 일이 있다면 반드시 분리하세요.

npm i dotenv

작업 폴더에 .env 파일을 만들고:

TEST_ID=본인아이디
TEST_PW=본인비밀번호

스크립트 맨 위에 한 줄 추가하고, 값을 불러다 씁니다.

import 'dotenv/config';

await page.getByRole('textbox', { name: '아이디' }).fill(process.env.TEST_ID);
주의

.env 파일은 절대 공유하지 마세요.

여러 스크립트 한 번에 돌리기

tests 폴더에 파일을 여러 개 넣으면 아래 한 줄로 전부 실행됩니다.

npx playwright test

특정 파일만 돌리려면:

npx playwright test tests/login.spec.js

셀렉터 안정화

녹화된 코드는 화면 구조에 밀착돼 있어 UI가 조금만 바뀌어도 깨집니다. 익숙해지면 아래처럼 바꿔두는 게 좋습니다.

약함안정적
page.locator('div > span:nth-child(3)')page.getByRole('button', { name: '검색' })
CSS 클래스 기반page.getByText('장바구니')

시작하기 좋은 대상

첫 자동화는 짧게 잡으세요.

  • 로그인 → 특정 지면 진입 (매번 손으로 하는 부분)
  • 테스트 데이터 세팅용 반복 클릭
  • 주요 화면이 오류 없이 뜨는지 확인하는 스모크

검증 로직이 복잡한 회귀 테스트는 익숙해진 뒤에 하는 걸 권합니다.
